## Decisões tomadas

### Decisão 1 — Projeto baseado em logística

O projeto será inspirado em operações reais de transportadoras, coletas, notas fiscais, mercadorias, destinos, prioridades e transferências.

### Decisão 2 — Aprendizado por projeto

Os conteúdos serão ensinados conforme forem necessários para evoluir o sistema.

### Decisão 3 — Código digitado pelo estudante

O estudante deverá digitar as linhas de código e compreender a lógica, evitando apenas copiar soluções completas.

### Decisão 4 — GitHub desde o início

O projeto será versionado desde a primeira etapa.

### Decisão 5 — GitHub Flow simplificado

Será utilizado o seguinte fluxo:

```text
main
  └── branch curta
        └── commits
              └── Pull Request
                    └── merge
```

### Decisão 6 — Sem burocracia exagerada

Issues, templates, automações e processos serão utilizados somente quando agregarem valor ao aprendizado ou à organização.

### Decisão 7 — Documentação como fonte oficial

Os documentos do repositório serão utilizados para retomar o projeto em novas conversas.

### Decisão 8 — Dois documentos principais

- `ROADMAP.md`: escopo e caminho completo;
- `PROGRESSO.md`: estado real e histórico.

### Decisão 9 — Monólito antes de microsserviços

O sistema começará simples e organizado. Microsserviços só serão considerados quando existir justificativa técnica.

### Decisão 10 — Tecnologias introduzidas progressivamente

Spring Boot, React, RabbitMQ, Redis, Docker, load balancer e outras tecnologias não serão antecipadas antes da compreensão dos fundamentos.
